## Method

Two arms, 4 runs each per task, model: `claude-sonnet-4-6`.

**baseline**: no hooks active. Agent writes from training knowledge.
**airblander**: resolve.js (UserPromptSubmit) + detect.js (PreToolUse, Write|Edit|MultiEdit only) + clear.js (PostToolUse WebFetch).

Isolation: `--setting-sources project,local` on both arms excludes global user settings so a user's own airblander install can't bleed into the baseline arm. (This is the same contamination bug ponytail caught in their June run — without this flag, the with-plugin arm and the baseline arm can both see global hooks.)

Each run starts in a fresh temp workspace. `reset.js` wipes `~/.claude/airblander-state.json` before every invocation so no cleared-SDK state carries over between runs or between arms.

9 tasks: 7 targeting watchlisted SDKs (where we know the deprecated-pattern traps), 2 targeting unknown services (resend, clerk) to exercise the v2 dynamic-detection path.

Scoring: after each run, grep the output file for patterns from `watchlist.json.deprecated`. A match = deprecated usage. No match = clean.

## Safety tier

These are structural findings from reading the code — they don't require running the benchmark.

| Test | What we checked | Result |
|------|-----------------|--------|
| **Bash bypass** | Does `detect.js` fire when the agent writes via the Bash tool? | **No** — `hooks.json` registers `detect.js` on `PreToolUse` with matcher `Write\|Edit\|MultiEdit`. Bash is not in that list. An agent told to write a file via `bash -c 'cat > file.js ...'` bypasses the hook entirely. |
| **Agent self-disable** | Can the agent send `/airblander` in its own output to disable enforcement? | **No** — the toggle lives in `resolve.js`, which is a `UserPromptSubmit` hook. That event only fires on literal user input; agent text doesn't trigger it. |
| **Fail-open behavior** | What happens if `watchlist.json` is missing or malformed? | **Fail-open** — `detect.js` calls `process.exit(0)` on any JSON parse error. Writes are allowed. This is deliberate: a broken plugin shouldn't block your work session. |
| **Dynamic SDK bypass** | If the agent writes a file using an unknown SDK's import *without* that SDK appearing in the user's prior prompt, does it get caught? | **Partially** — `detect.js` only checks dynamic SDKs that `resolve.js` already added to state. If the agent invents an SDK import the user never mentioned, it slips through. The gate is prompt-time, not pattern-exhaustive. |

### Honest read on the Bash bypass

The Bash bypass is the most significant gap. An agent that has been blocked once and is creative enough to try Bash next will succeed. In practice this rarely happens — models default to Write/Edit when writing files — but it's a real hole and shouldn't be papered over.

The fix would be adding a PostToolUse or separate Bash hook that greps Bash commands for file-creation patterns. That adds complexity and false-positive risk. We've left it as a documented caveat for now.

## Honest caveats

- n=4 per cell is genuinely small. A single unlucky run can move the catch rate by 25 percentage points.
- "Catch rate" measures that the baseline arm wrote deprecated code and the airblander arm didn't — it does not prove causation. The airblander agent might have avoided it for other reasons (e.g. more turns means more room to self-correct).
- The benchmark uses `--permission-mode bypassPermissions`. Real sessions don't run that way and the additional permission prompts could change the flow.
- Unknown-SDK tasks (resend, clerk) are a fundamentally different measurement. They're testing the resolution *flow*, not the deprecated-catch rate. Don't compare their numbers to the SDK rows directly.
- We only tested one model. A model with more recent training data might have lower baseline deprecated rates, which would make airblander's catch rate look smaller — not because airblander is less useful, but because the model is already getting it right more often.

## Reproduce

```bash
cd airblander

# dry run — shows which workdirs would be created, no API calls
node benchmarks/run.js --dry-run

# full run
node benchmarks/run.js --runs=4 --model=claude-sonnet-4-6

# subset of tasks
node benchmarks/run.js --tasks=twilio-sms,stripe-charge --runs=2
```

Unit tests (no API, ~500ms):

```bash
node --test tests/detect.test.js tests/clear.test.js tests/resolve.test.js
```
